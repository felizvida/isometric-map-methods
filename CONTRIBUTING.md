# Contributing

Open an issue or pull request with a concrete methods problem, expected behaviour and minimal synthetic reproduction. Run both test suites from the README. The maintainers review every candidate for publication before it is pushed.

Use invented values and generate fixtures in code, or the bundled tutorial sample. Do not attach site or organisation data, personnel information, real model parameters, photos, screenshots, deployment details, credentials or other source extracts. Link to public source landing pages instead. Changes to the toolkit must keep it free of data of its own and keep `map.html` loading nothing from the network. A change to `sample/` needs a licence that permits redistribution, updated attribution and provenance in `sample/README.md`, and a reviewed hash in `PUBLIC_FILES.json`.

New files require an entry in `PUBLIC_FILES.json` and review of every line and binary. Do not broaden ignore rules to accommodate data. Automated scans support, but do not replace, disclosure review.

Document limits and add regression tests for substantive bugs. Keep modules independent of any map, image service, hosting provider or organisation. Contributions use the repository's Apache-2.0 licence.
